## 项目概述

### 这个项目是做什么的？
AutomaticReviewGeneration 是一个**基于大语言模型（LLM）的自动综述生成系统**。简单来说，它能够：
- 从学术数据库自动搜索相关文献
- 下载并解析PDF文档
- 使用LLM（如Claude、GPT）自动提取关键信息
- 生成结构化的学术综述

### 为什么需要这个项目？
撰写学术综述通常需要：
1. 阅读大量文献（可能数十到上百篇）
2. 手工提取关键信息
3. 对比分析不同研究
4. 总结归纳形成综述

这个过程非常耗时。本项目通过自动化和LLM技术，可以大幅提高效率。

#### 核心功能解析

**2.1 生成提示词 (`XMLFormattedPrompt.py`)**

**什么是Prompt（提示词）？**
Prompt是给LLM的"问题+指令"。好的Prompt能让LLM返回更准确的答案。

**代码工作流程：**

```python
# 1. 读取PDF转换后的文本
doc = GetRefineContents(f.read())

# 2. 读取预定义的问题列表
with open('QuestionsForReview.txt', 'r') as f:
    content = f.readlines()

# 3. 组合成完整的Prompt
final_prompt = FormattedPromptHead + doc + FormattedPromptMiddle + questions + FormattedPromptEnd
```

**Prompt模板结构：**
```xml
<literature>
  [这里放文献的全文]
</literature>

<questions>
  1. 研究的主要催化剂是什么？
  2. 反应温度是多少？
  ...
</questions>

[指令：请按照XML格式返回答案，先引用原文，再回答问题]
```

**为什么使用XML格式？**
- 结构化：便于后续解析
- 明确性：LLM更容易理解边界
- 可靠性：减少格式错误

**2.2 调用LLM (`GetAllResponse.py`)**

**多线程并发处理：**

```python
def worker():
    """工作线程，处理一个Prompt"""
    while True:
        # 从队列获取任务
        prompt = prompt_queue.get_nowait()
        
        # 尝试获取可用的API（Claude或OpenAI）
        for semaphore, GetResponseFunction in zip(ClaudeAPISemaphore, ...):
            if semaphore.acquire(blocking=False):
                # 调用LLM
                response = GetResponseFunction(prompt)
                # 保存结果
                with open(f'answer.txt', 'w') as file:
                    file.write(response)
                break
```

**为什么要多线程？**
- LLM调用通常需要几秒到几十秒
- 多个文献可以并行处理
- 提高整体效率

**信号量（Semaphore）的作用：**
- Claude API: 限制1个并发（避免超速）
- OpenAI API: 限制3个并发
- 避免同时发送过多请求导致被封禁

**重试机制：**
```python
for Time in range(Repeat):  # 重复5次
    try:
        response = GetResponseFunction(prompt)
        break
    except Exception as e:
        # 记录错误，继续重试
        continue
```

## 数据流程

### 完整的数据转换过程

```
输入: 关键词 "catalysis CO2 reduction"
    ↓
步骤1: 搜索 → links = ["https://doi.org/10.1039/...", ...]
    ↓
步骤2: 下载 → PDF文件
    ↓
步骤3: 转换 → 文本文件 (RawFromPDF/10.1039_xxx.txt)
    ↓
步骤4: 生成Prompt → Prompt/Prompt10.1039_xxx.txt.PART0
    ↓
步骤5: 调用LLM → 10.1039_xxx/answer.PART0_0.txt (5个重复)
    ↓
步骤6: 整合 → BestParagraph1.txt, BestParagraph2.txt, ...
    ↓
输出: draft.txt (最终综述)
```

### 文件命名规则

- `Prompt{DOI}.txt.PART{N}`: Prompt文件，N是问题分组编号
- `answer.PART{N}_{T}.txt`: LLM回复，T是重复次数(0-4)
- `{N}Finished`: 标记文件，表示该部分已完成
- `BestParagraph{N}.txt`: 第N个问题的最佳段落

## 常见问题

### Q1: 为什么需要API密钥？
**A**: API密钥类似于"账号密码"，用于：
- 身份验证（确认你是合法用户）
- 计费（根据使用量收费）
- 限流（防止滥用）

### Q2: 什么是Elsevier、RSC、MDPI？
**A**: 这些是**学术出版商**：
- **Elsevier**: 最大的科技出版商（如ScienceDirect）
- **RSC**: 英国皇家化学学会
- **MDPI**: 开放获取出版商

每个出版商的网站结构不同，所以需要针对性的解析代码。

### Q3: 为什么要重复5次调用LLM？
**A**: 因为LLM的输出具有**随机性**：
- 同样的输入，每次输出可能不同
- 多次调用可以：
  - 提高可靠性（取最佳结果）
  - 交叉验证（确认一致性）
  - 覆盖更多角度

### Q4: CSV、JSON、YAML有什么区别？
**A**: 都是数据存储格式：
- **CSV**: 表格格式，适合Excel打开
- **JSON**: 键值对，适合程序读取
- **YAML**: 人类可读，适合配置文件
